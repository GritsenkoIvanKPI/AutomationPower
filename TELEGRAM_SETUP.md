# Заявки з сайту в Telegram — налаштування

Форми на всіх чотирьох сторінках (`index.html`, `21700.html`, `high-density.html`,
`ev-packs.html`) надсилають дані в один скрипт `send-form.php`, а він пересилає їх у Telegram.

```
браузер  ->  send-form.php  ->  api.telegram.org
                   ^
              config.php (токен, ніколи не комітиться і не віддається браузеру)
```

Токен **не потрапляє на сторінку**. Якби форма зверталася до Telegram напряму з JavaScript,
токен був би видимий кожному відвідувачу — а хто має токен, той керує ботом.

---

## 1. Створити бота

1. У Telegram написати [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Ввести назву й username бота.
3. BotFather віддасть **токен** виду `1234567890:AAE...`. Скопіювати.

## 2. Дізнатися chat_id

**Куди мають падати заявки** — зазвичай у групу, щоб їх бачили всі менеджери.

1. Створити групу, додати туди бота.
2. Написати в групу будь-яке повідомлення.
3. Відкрити в браузері:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
4. Знайти `"chat":{"id":-1001234567890`. Це і є `chat_id`.

> ID групи — відʼємний (`-100…`), приватного чату — додатний.
> Якщо `getUpdates` порожній — напишіть у групу ще раз і оновіть сторінку.

## 3. Створити config.php на сервері

Скопіювати `config.example.php` у `config.php` **на сервері** і вписати значення:

```php
return [
    'bot_token' => '1234567890:AAE...',
    'chat_id'   => '-1001234567890',
    'notify_email' => '',          // необовʼязково: копія заявки на пошту
    'rate_limit_per_hour' => 5,    // скільки заявок з однієї IP за годину
];
```

`config.php` у git не потрапляє (він у `.gitignore`) — це навмисно.

## 4. Перевірити

Відкрити в браузері:

```
https://automatonpower.com.ua/send-form.php?selftest=1
```

Має віддати JSON. Ключове:

| Поле | Має бути | Якщо ні |
|---|---|---|
| `config_present` | `true` | не створено `config.php` |
| `token_present` | `true` | не вписано токен |
| `chat_id` | ваш ID | не вписано chat_id |
| `can_send` | `true` | на хостингу немає ні cURL, ні `allow_url_fopen` — писати в підтримку |
| `php_ok` | `true` | потрібен PHP 7.4+ |

Токен у відповіді **не друкується** — тільки чи він є і яка в нього довжина.

Далі надіслати тестову заявку через форму на сайті.

---

## Вимоги до хостингу

- **PHP 7.4+** — сторінки статичні, але цей один скрипт потребує PHP.
- Вихідні HTTPS-запити (cURL або `allow_url_fopen`).

Якщо хостинг статичний (GitHub Pages, Netlify без функцій) — PHP не запрацює;
тоді ту саму логіку треба перенести у serverless-функцію.

## Що вміє скрипт

- **Пастка для ботів** — приховане поле `website`. Заповнене → відповідь «успіх», але
  нічого не надсилається, тож бот не має сигналу повторити спробу.
- **Ліміт частоти** — 5 заявок з IP за годину (налаштовується).
- **Валідація на сервері** — імʼя, телефон, email перевіряються ще раз, незалежно від браузера.
- **Тип виробу зі словника** — у Telegram потрапляє назва з переліку на сервері, а не
  довільний текст із браузера.
- **Помилки в лог, не в браузер** — текст помилки Telegram API може цитувати запит,
  тому назовні йде лише код (`delivery_failed`), а подробиці — у лог сервера.
- **Працює без cURL** — фолбек на потоковий запит, якщо розширення немає.

## Якщо заявки не приходять

1. `?selftest=1` — усі ключові поля `true`?
2. Бот доданий у групу і група не архівована?
3. Лог помилок PHP на хостингу — шукати рядки `send-form:`.
4. `chat_id` саме той (у групи він відʼємний)?
